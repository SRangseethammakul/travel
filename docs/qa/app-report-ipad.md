### บั๊ก

#### APP-T1: หน้า "ทริปของฉัน" บน iPad การ์ดทริปแคบกว่าบนมือถือ เครื่องหมายลบของยอดค้างจ่ายหลุดไปอยู่คนละบรรทัดกับตัวเลข
- Severity: medium (ตัวเลขเงินอ่านผิดได้ — "−" ค้างอยู่บรรทัดบน "฿7,202.67" สีแดงอยู่บรรทัดล่าง)
- Side: frontend
- Viewport: 820×1180, 768×1024, 1180×820 — ทำซ้ำได้ทั้ง 3 ขนาด (การ์ด 294px, span ยอดเงินสูง 41px = 2 บรรทัด)
- Screen / flow: 9 Trips `/trips` ในฐานะ `qa-t-viewer` (Member QA-T-Joy, −฿7,202.67) และ `qa-t-joiner` (Member QA-T-Vee, −฿5,169.33)
- Steps: 1. เปิด `/trips` ที่ความกว้าง 820 กับ User ที่มียอดค้างจ่าย
- Expected: การ์ดกว้างเต็มคอลัมน์เหมือนมือถือ ยอด "−฿7,202.67" อยู่บรรทัดเดียว (SPEC: แอปยืดได้ถึง 640px · mockup วาดที่ 390px จึงเป็นการ์ดคอลัมน์เดียว)
- Actual: `ul` ใช้ `sm:grid sm:grid-cols-2` ซึ่งเป็น breakpoint ตามความกว้างจอ (≥640px) แต่คอลัมน์ของแอปจำกัดที่ 640px → การ์ดกว้าง 294px (บนมือถือ 390px กว้าง ~350px) ชื่อทริปตัดเป็น 3 บรรทัด และ `<span>−฿7,202.67</span>` สูง 41px (ขึ้น 2 บรรทัด) — เมื่อมีทริปเดียว ครึ่งขวาของคอลัมน์ว่าง
- Evidence: `docs/qa/screenshots/ipad-app-t1-trips-card-768.png` · `frontend/src/app/trips/page.tsx:83` · `getComputedStyle(ul).gridTemplateColumns` = `294px 294px`
- แนะนำ: เอา `sm:grid-cols-2` ออก หรือใช้ container query (`@container`) แทน breakpoint จอ และใส่ `whitespace-nowrap` ให้ยอดเงิน

#### APP-T2: ผู้จัดทริปย่นวันทริปได้โดยไม่มีคำเตือน แผนของวันที่ถูกตัดหายไปจากหน้าจอแต่ยังอยู่ในระบบ
- Severity: medium (ข้อมูลไม่หายแต่มองไม่เห็นและแก้/ลบไม่ได้ · "ลงแผน" ในหน้า Places ยังนับรวม)
- Side: both (backend B2 รับ 200 · frontend ไม่เตือน)
- Viewport: 820×1180 (ไม่ขึ้นกับขนาดจอ)
- Screen / flow: แก้ไขทริป `/trips/[tripId]/edit` ในฐานะ `qa-t-owner` (owner)
- Steps: 1. ทริป 4 วัน ลง "QA-T-Hotel Susukino" วัน 1–4 2. เปิดแก้ไขทริป เปลี่ยนวันกลับจาก 24 เป็น 23 ธ.ค. 3. บันทึก 4. เปิดแผน `?day=4`
- Expected: เตือนหรือปฏิเสธเมื่อมี Plan Item อยู่นอกช่วงวันใหม่ (เหมือน City Legs ที่ action บอกว่า backend ตรวจ) หรือย้ายไป "ยังไม่จัดวัน" — SPEC เปิดไว้ในกรณีขอบ
- Actual: `PATCH /api/trips/:id` → 200 · `GET /plan` ยังมีรายการ day 4 · แถบวันเหลือ 1–3, `?day=4` แสดงวัน 1 · Places ยังขึ้น "Susukino · 2 ที่ · ลงแผน 2" · ย่นเหลือ 2 วันผ่าน API ก็ 200 เช่นกัน (ทำซ้ำ 2 ครั้ง) · ขยายกลับเป็น 4 วันแล้วรายการกลับมา
- Evidence: API days ก่อน/หลัง `[transit,1,1,1,2,3,4]` ทั้งสองครั้ง
- Related: SPEC "กรณีขอบ" (เปิดอยู่), Edit Trip เป็นหน้าใหม่ไม่มี mockup

### Spec questions

- **iPad layout:** SPEC "ยืดได้ถึง 640px ให้ใช้ได้ทั้งมือถือ 320px ขึ้นไปและแท็บเล็ต" vs เรื่องที่เปิดอยู่ "หน้าจอ iPad และคอม เริ่มจากแผนรายวันแบบหลายวันพร้อมลากวาง และค่าใช้จ่ายคู่กับสรุป" — ตอนนี้ที่ 1180 แนวนอน ขอบว่างข้างละ 270px (46% ของจอ) ควรตัดสินว่าจะออกแบบ layout แท็บเล็ตเมื่อไร
- **Edit Trip:** แก้ได้แค่ชื่อ ปลายทาง วัน — SPEC บอกผู้จัดทริป "แก้ได้ทุกอย่าง" แต่ไม่มี mockup ของหน้านี้ · งบประมาณ สีหน้าปก และจุดนัดพบ ควรแก้ได้ไหม

### ยังไม่ได้ทดสอบ

- LINE / Google login จริง (ไม่มี credential) และ logout ทุกอุปกรณ์
- เปิดสลิปผ่าน signed URL (ผูกกับ `localhost:3000` แต่ทดสอบบน `ipad.localhost`) และลิงก์หมดอายุ 5 นาที
- backend หยุด / เน็ตช้า — หยุด backend ไม่ได้เพราะ agent มือถือใช้อยู่
- การ redirect ฝั่ง server ภายใน iframe ทดสอบไม่ได้ (iframe ขึ้นหน้า error ของ Chrome) — ตรวจแบบเปิดเต็มหน้าและด้วย curl แทน
- คีย์บอร์ดบนจอ iPad (ทำให้แนวนอนเหลือความสูงน้อยลง), Safari iPadOS จริง, การแตะ/ปัด — ทดสอบใน Chrome desktop จำลองขนาดเท่านั้น
- ManageTags, TripRoute, หน้าเอกสาร, รีเซ็ตลิงก์เชิญ, สองแท็บแก้ Expense เดียวกัน
